# Core Rules

## 基本原则

- 先理解问题，再动手实现。
- 先保留上下文，再抽象结论。
- 小步推进，频繁验证。
- 优先做能证明价值的最小版本。
- 不为了“看起来工程化”而引入复杂结构。

## 修改原则

- 修改范围应尽量贴近任务目标。
- 不改无关文件，不做无关格式化。
- 遇到已有内容不清楚时，先补充说明或提出假设。
- 任何性能、质量、成本相关结论都必须能复现。

## 项目叙事原则

本仓库服务于 AI infra 方向成长，项目应尽量体现：

- 请求路径和系统边界。
- SLO、延迟、吞吐、成本和可观测性。
- benchmark 和实验方法。
- 从传统 infra 能力迁移到 LLM infra 问题的过程。
