# AI Collaboration Rules

## Vibecoding 工作流

本仓库鼓励使用 AI 辅助开发，但要求每次任务都留下可理解、可复查的工程轨迹。

推荐流程：

1. 读上下文：README、AGENTS、rules、相关 docs。
2. 明确目标：本次要解决什么，不解决什么。
3. 小步修改：先做最小有效变更。
4. 验证结果：运行可用的检查、测试或文档校验。
5. 总结变更：说明修改文件、验证方式和后续风险。

## AI Agent 约束

- 不臆造项目状态。
- 不静默覆盖用户改动。
- 不用大段重写替代精准修改，除非用户明确要求重写。
- 不提交 secrets、环境文件、依赖缓存或构建产物。
- 不把未经验证的 benchmark 结论写成事实。

## 适合 AI 做的事情

- 起草项目计划、设计文档和 ADR。
- 搭建目录结构和基础配置。
- 生成测试、benchmark harness 和报告模板。
- 做代码阅读总结和架构图。

## 需要人类确认的事情

- 项目对外名称。
- GitHub 仓库可见性。
- 是否开源。
- benchmark 结论是否可对外引用。
- 涉及账号、token、云资源和付费 API 的操作。
